# ТЗ для разработки MVP: AI Content Studio / BrandMate AI

## 1. Описание идеи

Нужно разработать self-hosted веб-приложение для генерации контента для соцсетей с помощью ИИ.

Продукт должен работать как персональный AI-контент-ассистент, который запоминает не только бизнес пользователя, но и разные контент-профили: личный блог, экспертную тему, проект, нишу, хобби, медиа-рубрику или любой другой пользовательский сценарий. Для каждого профиля ассистент хранит аудиторию, позиционирование, стиль общения, визуальные предпочтения, платформы и прошлые удачные материалы.

Главная идея продукта:

> Пользователь один раз создает контент-профиль, например “личные посты про AI”, “экспертный блог”, “кофейня” или “мем-аккаунт”, а дальше просто пишет задачу: “Сделай пост на такую-то тему”. Ассистент уже помнит аудиторию, стиль, ограничения, платформы и генерирует контент без лишних вопросов.

В MVP приложение работает в режиме одного локального пользователя без регистрации, но внутри этого пользователя можно создать несколько контент-профилей. Модель `User` остается в архитектуре как технический задел для будущего multi-user режима.

Генерация должна поддерживать два рабочих сценария:

1. Автоматический режим: пользователь задает тему, профиль и платформу, а система сама пишет готовый пост.
2. Пошаговый режим: система анализирует тему, предлагает расширенные углы подачи, варианты хуков, черновик, правки, финальную версию, image prompt и оценку под выбранную платформу.

Приложение должно запускаться локально на компьютере или на арендованном сервере. Доступ к веб-интерфейсу должен быть возможен с компьютера и телефона через браузер.

В будущем нужно добавить Telegram-бота, чтобы пользователь мог обращаться к ассистенту с телефона.

---

## 2. Основная цель MVP

Сделать первую рабочую версию веб-приложения, где пользователь может:

1. Создать и редактировать несколько контент-профилей.
2. Создать профиль вручную или описать его свободным текстом, чтобы AI сам заполнил характеристики.
3. Создавать и сохранять стили общения.
4. Создавать и сохранять стили изображений.
5. Генерировать посты для соцсетей в автоматическом и пошаговом режиме.
6. Получать идеи сторис, CTA, промпты для изображений и варианты хуков.
7. Получать базовую оценку поста под выбранную платформу: ясность, сила хука, соответствие платформе, виральный потенциал и риски.
8. Сохранять историю всех генераций, промежуточных вариантов, тегов и статусов.
9. Выбирать модель ИИ для генерации.
10. Запускать приложение локально или на сервере.

## 3. Рекомендуемый стек

### Backend

Использовать:

- Python
- FastAPI
- SQLAlchemy
- SQLite для первой версии
- PostgreSQL как опция для продакшена

Приложение должно запускаться через Docker Compose:

```text
http://localhost:3000
```


## 5. Основные сущности

### User

Для MVP используется один локальный пользователь без регистрации и ролей.

`User` нужен как технический задел, чтобы позже добавить несколько пользователей, авторизацию и изоляцию данных без переписывания схемы.

Поля:

```text
id
email
password_hash
created_at
```

Если регистрация в MVP не делается, приложение создает `default user` при первом запуске.

---

### Content Profile

Контент-профиль — главная память ассистента.

Один локальный пользователь может создать несколько профилей.

Пользователь сам задает тип профиля или описывает его свободным текстом. Система должна уметь разобрать короткое описание и предложить структурированные характеристики: нишу, аудиторию, позиционирование, цели, рубрики, платформы, стиль и ограничения.

`profile_type` хранит свободную пользовательскую формулировку, например “личный блог про AI”, “экспертный профиль”, “мем-аккаунт”, “заметки о спорте” или “кофейня”. Это не enum, поле принимает любой текст.

Поля:

```text
id
user_id
name
profile_type
source_description
niche
description
offer_or_focus
audience
geography
tone
goals
platforms
language
positioning
content_pillars
platform_strategy
favorite_words
forbidden_words
avoid_topics
additional_notes
created_at
updated_at
```

Пример данных:

```json
{
```

Главная рабочая страница.

- выбранный стиль общения;
- выбранный стиль изображения;
- режим генерации:
  - автоматический;
  - пошаговый;
- платформы:
  - Instagram
  - Facebook
  - X/Twitter
  - LinkedIn
- формат:
  - пост
  - сторис
  - Reels script
  - идея креатива
  - image prompt
- длина:
  - короткий
  - средний
  - длинный
- язык;
- модель ИИ;
- количество вариантов;
- чекбокс “сгенерировать изображение сразу”;
- чекбокс “сохранить в историю”.

#### Автоматический режим

Пользователь задает тему, профиль, платформу и формат. Система сразу возвращает готовый результат, image prompt и базовую оценку.

#### Пошаговый режим

Пользователь проходит цепочку:

1. Вводит тему или короткую идею.
2. AI анализирует тему и предлагает 3–5 более сильных углов подачи.
3. Пользователь выбирает угол или просит предложить еще.
4. AI предлагает 5–10 вариантов хуков.
5. Пользователь выбирает хук.
6. AI пишет черновик.
7. Пользователь вносит правки свободным текстом.
8. AI делает финальную версию.
9. AI генерирует image prompt или несколько промптов.
10. AI оценивает результат под выбранную платформу.

После генерации показать:

- Instagram caption;
- Facebook version;
- X/Twitter version;
- LinkedIn version, если выбрано;
- Stories;
- Reels idea;
- CTA;
- image prompt;
- варианты хуков;
- анализ и рекомендации под платформу;
- виральный потенциал;
- изображение, если включена генерация изображений.

Кнопки после результата:

- Сохранить
- Скопировать
- Сделать короче
- Сделать более продающим
- Меньше эмодзи

- Улучшить хук

## 8. Логика генерации поста

Когда пользователь отправляет задачу на генерацию, backend должен:

1. Получить выбранный контент-профиль.
2. Получить выбранный стиль общения.
3. Получить выбранный стиль изображения.
4. Получить режим генерации: `auto` или `guided`.
5. Получить последние 3–5 похожих постов из истории, если нужно.
6. Собрать системный промпт.
7. Отправить запрос в OpenAI API.
8. Получить структурированный ответ.
9. Выполнить базовую оценку результата под выбранные платформы.
10. Сохранить результат или шаг сессии в базу.
11. Вернуть результат на frontend.

### Автоматический режим

В автоматическом режиме backend за один запрос возвращает готовый пост, CTA, image prompt и анализ результата.

### Пошаговый режим

В пошаговом режиме backend создает `Generation Session` и обрабатывает каждый шаг отдельно:

1. `topic_analysis` — понять тему, аудиторию, потенциальные углы и риски.
2. `angle_selection` — предложить расширенные углы подачи.
3. `hook_generation` — предложить варианты хуков.
4. `draft_generation` — написать первый черновик.
5. `revision` — принять правки пользователя и переписать текст.
6. `finalization` — подготовить финальную версию.
7. `image_prompt` — создать промпт или несколько промптов для изображения.
8. `platform_analysis` — оценить результат под выбранную платформу.

Каждый шаг сохраняется, чтобы пользователь мог вернуться к истории работы, посмотреть отвергнутые хуки и восстановить предыдущую версию.

## 11. Функция “Запомнить стиль”

После генерации пользователь может нажать кнопку:

> Запомнить этот стиль

Или написать:

> Запомни: мне нравятся короткие посты без вопросов в конце.

Система должна предложить сохранить новое правило в выбранный Text Style.

Пример нового правила:

```text
Писать короткие посты 500–700 символов. Не заканчивать посты вопросом. Использовать мягкий CTA.
```

Это правило добавляется в поле `rules` выбранного стиля.

## 12. Генерация изображений

В MVP можно сделать два режима работы с изображениями:

### Режим 1: только image prompt

Система генерирует промпт для изображения.

Это проще и дешевле.

### Режим 2: генерация изображения через API

Если пользователь включает чекбокс “Generate image”, backend отправляет prompt в image generation API.

Результат сохраняется в `image_url` или локальную папку.

Для MVP достаточно сначала сделать только image prompt, а генерацию изображений добавить вторым этапом.

1. Приложение запускается командой:

```bash
docker compose up
```

2. Пользователь может открыть веб-интерфейс:

```text
http://localhost:3000
```

3. Пользователь может создать и сохранить несколько контент-профилей.

12. Поддерживаются статусы `draft`, `liked`, `planned`, `published`, `archived`.
13. Старые посты можно открыть, скопировать и повторно использовать.

## 20. Главная формулировка задачи для AI-разработчика

Сделай self-hosted веб-приложение AI Content Studio.

Это приложение должно быть персональным AI-ассистентом для создания контента в соцсети. В MVP есть один локальный пользователь без регистрации, но он может создать несколько контент-профилей: бизнес, личный блог, экспертную тему, проект, развлекательный аккаунт или любой собственный тип. Для каждого профиля пользователь сохраняет стиль общения, визуальные стили, платформы, аудиторию, позиционирование и ограничения. Затем пользователь вводит тему поста и выбирает автоматический или пошаговый режим генерации. Система использует сохраненную память профиля и генерирует адаптированные посты для Instagram, Facebook, X/Twitter и LinkedIn, а также сторис, CTA, варианты хуков, prompt для изображения и базовую оценку результата под платформу. Все генерации, правки, теги и статусы сохраняются в историю. Приложение должно запускаться локально или на сервере через Docker Compose и быть доступным из браузера на компьютере и телефоне.
